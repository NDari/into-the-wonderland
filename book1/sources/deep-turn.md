## Sourced claims

### T1. The reader's pipeline: hand-built features, then a classifier
- Sources: `lecun2015deep`, `goodfellow2016deep`, `hinton2012deep`.
- Quotes: LeCun et al., p. 436: "Conventional machine-learning techniques were limited in their ability to process natural data in their raw form. For decades, constructing a pattern-recognition or machine-learning system required careful engineering and considerable domain expertise to design a feature extractor that transformed the raw data (such as the pixel values of an image) into a suitable internal representation or feature vector from which the learning subsystem, often a classifier, could detect or classify patterns in the input." Next sentence: "Representation learning is a set of methods that allows a machine to be fed with raw data and to automatically discover the representations needed for detection or classification." p. 437: "Many of the current practical applications of machine learning use linear classifiers on top of hand-engineered features." p. 438: "To make classifiers more powerful, one can use generic non-linear features, as with kernel methods, but generic features such as those arising with the Gaussian kernel do not allow the learner to generalize well far from the training examples. The conventional option is to hand design good feature extractors, which requires a considerable amount of engineering skill and domain expertise. But this can all be avoided if good features can be learned automatically using a general-purpose learning procedure. This is the key advantage of deep learning." (reference numbers dropped).
- Goodfellow et al., p. 4: "Learned representations often result in much better performance than can be obtained with hand-designed representations." And: "A representation learning algorithm can discover a good set of features for a simple task in minutes, or for a complex task in hours to months. Manually designing features for a complex task requires a great deal of human time and effort; it can take decades for an entire community of researchers." p. 10, Figure 1.5: flowcharts for "Rule-based systems", "Classic machine learning" (hand-designed features, then a learned mapping), "Representation learning", and "Deep learning" (simple features, then "Additional layers of more abstract features"); caption: "Shaded boxes indicate components that are able to learn from data."
- Speech, the same pattern: `hinton2012deep` p. 83: inputs were MFCCs or PLPs "computed from the raw waveform and their first- and second-order temporal differences. This nonadaptive but highly engineered preprocessing of the waveform is designed to discard the large amount of information in waveforms that is considered to be irrelevant for discrimination".
- Vision, the same pattern: the ILSVRC 2010 and 2011 winners were feature pipelines with SVMs (T14).
- Note: this is the chapter's bridge. The reader's core 2000s skill (feature engineering, then logistic regression or an SVM) is exactly LeCun's "conventional option". Goodfellow's Figure 1.5 is a ready-made diagram to redraw. LeCun's remark about the Gaussian kernel is the honest link to the SVM the reader knows; it is a claim by interested parties (three deep-learning pioneers) and should be attributed, not stated as fact.

### T2. Depth as a hierarchy of learned features
- Sources: `lecun2015deep`, `goodfellow2016deep`, `krizhevsky2012imagenet`.
- Quotes: LeCun et al., p. 436: "An image, for example, comes in the form of an array of pixel values, and the learned features in the first layer of representation typically represent the presence or absence of edges at particular orientations and locations in the image. The second layer typically detects motifs by spotting particular arrangements of edges, regardless of small variations in the edge positions. The third layer may assemble motifs into larger combinations that correspond to parts of familiar objects, and subsequent layers would detect objects as combinations of these parts. The key aspect of deep learning is that these layers of features are not designed by human engineers: they are learned from data using a general-purpose learning procedure." Also p. 436: "We think that deep learning will have many more successes in the near future because it requires very little engineering by hand, so it can easily take advantage of increases in the amount of available computation and data." Goodfellow et al., p. 5: "Deep learning solves this central problem in representation learning by introducing representations that are expressed in terms of other, simpler representations. Deep learning enables the computer to build complex concepts out of simpler concepts."
- Direct evidence in a primary source: Krizhevsky et al., p. 6, Figure 3 caption: "96 convolutional kernels of size 11x11x3 learned by the first convolutional layer on the 224x224x3 input images." p. 7: "The network has learned a variety of frequency- and orientation-selective kernels, as well as various colored blobs." p. 8, on the last hidden layer: "If two images produce feature activation vectors with a small Euclidean separation, we can say that the higher levels of the neural network consider them to be similar." and "Notice that at the pixel level, the retrieved training images are generally not close in L2 to the query images in the first column. For example, the retrieved dogs and elephants appear in a variety of poses." ("x" stands for the multiplication sign in the source.)
- Note: LeCun's edges, motifs, parts, objects is hedged ("typically", "may"); keep the hedges. The first-layer claim is backed by AlexNet's Figure 3; the deeper layers rest on LeCun (the standard primary source, Zeiler and Fergus, was not fetched). AlexNet p. 8 is a good bridge: nearest neighbours in pixel space (which the reader knows) fail, nearest neighbours in the learned 4096-number space work. That foreshadows `embeddings`.

### T3. The argument for depth, and the belief that deep nets could not be trained (as of 2006)
- Source: `bengio2007greedy`.
- Quotes: abstract (p. 1, PDF): "Complexity theory of circuits strongly suggests that deep architectures can be much more efficient (sometimes exponentially) than shallow architectures, in terms of computational elements required to represent some functions." and "However, until recently it was not clear how to train such deep networks, since gradient-based optimization starting from random initialization appears to often get stuck in poor solutions." p. 1 (PDF): "Kernel machines (not only those with a local kernel) have a shallow architecture, i.e., only two levels of data-dependent computational elements." p. 2 (PDF): "However, until recently, it was believed too difficult to train deep multi-layer neural networks. Empirically, deep networks were generally found to be not better, and often worse, than neural networks with one or two hidden layers (Tesauro, 1992). As this is a negative result, it has not been much reported in the machine learning literature."
- Also: p. 1 (PDF), the parity example: parity of d inputs "requires O(2^d) examples and parameters to be represented by a Gaussian SVM ..., O(d^2) parameters for a one-hidden-layer neural network, O(d) parameters and units for a multi-layer network with O(log2 d) layers" (exponents written with ^).
- Note: the "shallow vs deep" framing explicitly places the reader's SVM in the "shallow" column. Use the parity example only in words (no derivation, per D-002). Bengio is an interested party; attribute.

### T4. Hinton, Osindero, and Teh (2006): deep belief nets, trained one layer at a time
- Source: `hinton2006fast`.
- Location: pp. 1527-1529, 1540-1541, 1544, 1554.
- Quotes: abstract (p. 1527): "Using complementary priors, we derive a fast, greedy algorithm that can learn deep, directed belief networks one layer at a time, provided the top two layers form an undirected associative memory. The fast, greedy algorithm is used to initialize a slower learning procedure that fine-tunes the weights using a contrastive version of the wake-sleep algorithm. After fine-tuning, a network with three hidden layers forms a very good generative model of the joint distribution of handwritten digit images and their labels. This generative model gives better digit classification than the best discriminative learning algorithms."
- The boosting analogy (p. 1529): "The greedy algorithm bears some resemblance to boosting in its repeated use of the same "weak" learner, but instead of reweighting each data vector to ensure that the next step learns something new, it re-represents it."
- Headline result (p. 1529): "Section 6 shows the pattern recognition performance of a network with three hidden layers and about 1.7 million weights on the MNIST set of handwritten digits. When no knowledge of geometry is provided and there is no special preprocessing, the generalization performance of the network is 1.25% errors on the 10,000-digit official test set. This beats the 1.5% achieved by the best backpropagation nets when they are not handcrafted for this particular application. It is also slightly better than the 1.4% errors reported by Decoste and Schoelkopf (2002) for support vector machines on the same task."
- Architecture (p. 1528, Figure 1): a "28 x 28 pixel image", two layers of "500 units", "2000 top-level units", and "10 label units". Table 1 (p. 1544) writes it "784 -> 500 -> 500 <-> 2000 <-> 10" (arrows simplified).
- Cost (p. 1540): "The greedy training took a few hours per layer in MATLAB on a 3 GHz Xeon processor, and when it was done, the error rate on the test set was 2.49%". p. 1541: after a further 59 epochs, "making the total learning time about a week. The final network had an error rate of 1.25%." Footnote 9 (p. 1541): left running at a small learning rate for six weeks, test error fluctuated "between 1.12% and 1.31%".
- The comparison table (p. 1544, Table 1): permutation-invariant MNIST: this model 1.25; "Support vector machine: degree 9 polynomial kernel" 1.4; backprop 784-500-300-10 1.51; backprop 784-800-10 1.53. Unpermuted images with extra distorted data: a convolutional network 0.4; virtual SVM 0.56; LeNet5 0.8 (affine distortions) and 0.95.
- The caveat in the authors' words (p. 1540): "no special preprocessing or enhancement of the training set, so an unknown but fixed random permutation of the pixels would not affect the learning algorithm. For this "permutation-invariant" version of the task, the generalization performance of our network was 1.25% errors".
- Dates (p. 1554): "Received June 8, 2005; accepted November 8, 2005." Communicated by Yann Le Cun (p. 1527).
- Note: two things for the chapter. (1) The 2006 result beat the SVM only on the "permutation-invariant" version of MNIST (the network is not told that pixels have neighbours). Convolutional nets with distorted data were already at 0.4% to 0.95% (same table). The honest claim is "a fully connected deep network, given no knowledge of images, beat the best SVM", not "deep learning beat everything on MNIST". This connects exactly to `structure` S8 (the SVM "would do as well if the image pixels were encrypted"). (2) The boosting sentence is a bridge to a method the reader knows. The DBN machinery (RBMs, complementary priors, wake-sleep, contrastive divergence) is out of scope for Book 1 beyond one sentence: "each layer was first trained, without labels, to model the layer below it".

### T5. Hinton and Salakhutdinov (2006): a deep autoencoder as nonlinear PCA, and the three conditions
- Source: `hinton2006reducing`.
- Quotes: abstract (p. 504): "High-dimensional data can be converted to low-dimensional codes by training a multilayer neural network with a small central layer to reconstruct high-dimensional input vectors. Gradient descent can be used for fine-tuning the weights in such "autoencoder" networks, but this works well only if the initial weights are close to a good solution. We describe an effective way of initializing the weights that allows deep autoencoder networks to learn low-dimensional codes that work much better than principal components analysis as a tool to reduce the dimensionality of data." p. 504: "A simple and widely used method is principal components analysis (PCA), which finds the directions of greatest variance in the data set and represents each data point by its coordinates along each of these directions. We describe a nonlinear generalization of PCA". p. 505: "It is difficult to optimize the weights in nonlinear autoencoders that have multiple hidden layers. With large initial weights, autoencoders typically find poor local minima; with small initial weights, the gradients in the early layers are tiny, making it infeasible to train autoencoders with many hidden layers." (reference numbers dropped).
- Numbers: p. 505, Fig. 2 caption: on face patches, 30-dimensional codes, "The average squared errors are 126 and 135" (autoencoder vs PCA); on MNIST digits, 3.00 for the 30-dimensional autoencoder, against 8.01 and 13.87 for 30-dimensional logistic PCA and standard PCA. p. 506, Fig. 3: two-dimensional codes for MNIST from PCA versus a "784-1000-500-250-2 autoencoder"; Fig. 4: document codes from "two-dimensional LSA" versus a "2000-500-250-125-2 autoencoder". p. 507: on MNIST, "the best reported error rates are 1.6% for randomly initialized backpropagation and 1.4% for support vector machines. After layer-by-layer pretraining in a 784-500-500-2000-10 network, backpropagation using steepest descent and a small learning rate achieves 1.2%".
- The thesis sentence (p. 507): "It has been obvious since the 1980s that backpropagation through deep autoencoders would be very effective for nonlinear dimensionality reduction, provided that computers were fast enough, data sets were big enough, and the initial weights were close enough to a good solution. All three conditions are now satisfied."
- Note: this is the best single bridge in the chapter: the reader knows PCA and LSA; here a deep network does both better, in Science, in 2006. The p. 507 sentence names the chapter's three themes (compute, data, getting deep nets to train) in the words of the person most associated with the turn; it is a strong epigraph candidate. The p. 505 sentence ("gradients in the early layers are tiny") ties back to vanishing gradients in `structure`. The Fig. 2 numbers are on different data sets; compare within a data set only.

### T6. Bengio et al. (2007): layer-wise pretraining helps, and why
- Source: `bengio2007greedy`.
- Quotes: abstract (p. 1, PDF): "Our experiments also confirm the hypothesis that the greedy layer-wise unsupervised training strategy mostly helps the optimization, by initializing weights in a region near a good local minimum, giving rise to internal distributed representations that are high-level abstractions of the input, bringing better generalization."
- Numbers (p. 6, PDF, Table 2, MNIST test error, Experiment 2): "DBN, unsupervised pre-training" 1.2%; "Deep net, auto-associator pre-training" 1.4%; "Deep net, supervised pre-training" 2.0%; "Deep net, no pre-training" 2.4%; "Shallow net, no pre-training" 1.9%. Architecture (p. 6): "784 inputs, 10 outputs, 3 hidden layers ... (typically selected layer sizes are between 500 and 1000)". Caption: "On MNIST, differences of more than .1% are statistically significant."
- pp. 6-7 (PDF): the results "clearly show that the greedy unsupervised layer-wise pre-training gives much better results than the standard way to train a deep network (with no greedy pre-training) or a shallow network, and that, without pre-training, deep networks tend to perform worse than shallow networks."
- p. 7 (PDF), Experiment 3: "all the networks, even those without greedy layer-wise pre-training, perform almost perfectly on the training set", and with no pre-training "the results obtained without pre-training were found to have extremely large variance indicating high sensitivity to initial conditions."
- Note: Table 2 is a clean, small piece of evidence the reader can read like a 2000s results table: in 2006-2007, a deep net trained the old way did worse than a shallow one (2.4% vs 1.9%), and pretraining reversed that (1.2%). The auto-associator row shows the idea is not tied to Boltzmann machines. Experiment 3's "almost perfectly on the training set" matters: the problem was partly generalization, not only optimization; the authors' own reading is optimization. Do not overstate. See D2 for how this was later revised.

### T7. How later accounts date and credit the revival
- Sources: `goodfellow2016deep`, `lecun2015deep`, `schmidhuber2014deep`.
- Quotes: Goodfellow et al., p. 13, Figure 1.7 caption: "The current and third wave, deep learning, started around 2006 (Hinton et al., 2006; Bengio et al., 2007; Ranzato et al., 2007a) and is just now appearing in book form as of 2016." p. 18: "The third wave of neural networks research began with a breakthrough in 2006. Geoffrey Hinton showed that a kind of neural network called a deep belief network could be efficiently trained using a strategy called greedy layer-wise pretraining (Hinton et al., 2006) ... The other CIFAR-affiliated research groups quickly showed that the same strategy could be used to train many other kinds of deep networks (Bengio et al., 2007; Ranzato et al., 2007a) and systematically helped to improve generalization on test examples." p. 18: "The third wave began with a focus on new unsupervised learning techniques and the ability of deep models to generalize well from small datasets, but today there is more interest in much older supervised learning algorithms and the ability of deep models to leverage large labeled datasets." p. 141: "The current deep learning renaissance began when Hinton et al. (2006) demonstrated that a neural network could outperform the RBF kernel SVM on the MNIST benchmark." (but see D6). p. 526: "The deep learning renaissance of 2006 began with the discovery that this greedy learning procedure could be used to find a good initialization for a joint learning procedure over all the layers, and that this approach could be used to successfully train even fully connected architectures ... Prior to this discovery, only convolutional deep networks or networks whose depth resulted from recurrence were regarded as feasible to train."
- LeCun et al., p. 439: "Interest in deep feedforward networks was revived around 2006 by a group of researchers brought together by the Canadian Institute for Advanced Research (CIFAR). The researchers introduced unsupervised learning procedures that could create layers of feature detectors without requiring labelled data." (reference numbers dropped).
- Schmidhuber, p. 21 (section 5.15): "While learning networks with numerous non-linear layers date back at least to 1965 (Sec. 5.3), and explicit DL research results have been published at least since 1991 (Sec. 5.9, 5.10), the expression Deep Learning was actually coined around 2006, when unsupervised pre-training of deep FNNs helped to accelerate subsequent SL through BP (Hinton and Salakhutdinov, 2006; Hinton et al., 2006)."
- Note: all three agree that something turned around 2006 and that it was layer-wise pretraining of deep, fully connected nets. They differ on how new deep learning was (D1). Goodfellow p. 526 is useful: before 2006, convolutional and recurrent nets (the subject of `structure`) were the only deep nets thought trainable; 2006 extended that to plain stacks of layers. The "2006" date and the CIFAR group are safe; "Hinton invented deep learning in 2006" is not.

### T8. Why graphics processors suit neural networks
- Sources: `goodfellow2016deep`, `raina2009large`, `schmidhuber2014deep`.
- Quotes: Goodfellow et al., p. 439: "Video game rendering requires performing many operations in parallel quickly. Models of characters and environments are specified via lists of 3-D coordinates of vertices. Graphics cards must perform matrix multiplication and division on many vertices in parallel to convert these 3-D coordinates into 2-D on-screen coordinates." p. 440: "For example, each vertex in the same rigid object will be multiplied by the same matrix; there is no need to evaluate an if statement per vertex to determine which matrix to multiply by. The computations are also entirely independent of each other, and thus may be parallelized easily." And: "Together, this results in graphics cards having been designed to have a high degree of parallelism and high memory bandwidth, at the cost of having a lower clock speed and less branching capability relative to traditional CPUs. Neural network algorithms require the same performance characteristics as the real-time graphics algorithms described above. Neural networks usually involve large and numerous buffers of parameters, activation values, and gradient values, each of which must be completely updated during every step of training." And: "GPUs offer a compelling advantage over CPUs because of their high memory bandwidth. Neural network training algorithms typically do not involve much branching or sophisticated control, so they are appropriate for GPU hardware. Since neural networks can be divided into multiple individual "neurons" that can be processed independently from the other neurons in the same layer, neural networks easily benefit from the parallelism of GPU computing." p. 440: "The popularity of graphics cards for neural network training exploded after the advent of general purpose GPUs." and "NVIDIA's CUDA programming language provided a way to write this arbitrary code in a C-like language." p. 441: "This platform was rapidly adopted by deep learning researchers soon after it became available (Raina et al., 2009; Ciresan et al., 2010)."
- Raina et al., p. 2 (PDF): "Meanwhile, the raw clock speed of single CPUs has begun to hit a hardware power limit, and most of the growth in processing power is increasingly obtained by throwing together multiple CPU cores, instead of speeding up a single core". And: "The typical graphics card shipped with current desktops contains over a hundred processing cores, and has a peak memory bandwidth several times higher than modern CPUs." Figure 1 caption: "Nvidia GeForce GTX 280 graphics card, with 240 total cores (30 multiprocessors with 8 stream processors each)." And: "There is of course a tradeoff, this parallelism is obtained by devoting many more transistors to data processing, rather than to caching and control flow, as in a regular CPU core." (source prints an em-dash after "tradeoff"). p. 3 (PDF): the main bottleneck is often "transferring data between RAM and the GPU's global memory" (but see D7 on the example that follows).
- Schmidhuber, p. 8: "GPUs are widely used for video games, a huge and competitive market that has driven down hardware prices. GPUs excel at the fast matrix and vector multiplications required not only for convincing virtual realities but also for NN training, where they can speed up learning by a factor of 50 and more."
- Note: the mechanism the chapter needs is Goodfellow's: a layer is one big matrix product, each output number is an independent sum of products, so thousands of simple cores can work at once; games had already paid for such chips. Example 1 below makes it concrete. Memory bandwidth (moving numbers in and out) matters as much as arithmetic; say so in one sentence. Do not cite a FLOPS figure for any 2009-2012 card; none was located in a fetched source.

### T9. Raina, Madhavan, and Ng (2009): GPUs for deep unsupervised learning
- Source: `raina2009large`.
- Quotes and numbers: abstract (p. 1, PDF): "We argue that modern graphics processors far surpass the computational capabilities of multicore CPUs, and have the potential to revolutionize the applicability of deep unsupervised learning methods." "Our implementation of DBN learning is up to 70 times faster than a dual-core CPU implementation for large models. For example, we are able to reduce the time required to learn a four-layer DBN with 100 million free parameters from several weeks to around a single day. For sparse coding, we develop a simple, inherently parallel algorithm, that leads to a 5 to 15-fold speedup over previous methods."

- Source: `krizhevsky2012imagenet` (proceedings pages 1-9).

### T16. AlexNet's own account of what made it work (only what AlexNet used; details belong to `toolkit`)
- Source: `krizhevsky2012imagenet`.
- Quotes: p. 2: "Sections 3.1-3.4 are sorted according to our estimation of their importance, with the most important first." Section 3.1 is ReLU, 3.2 multiple GPUs, 3.3 local response normalization, 3.4 overlapping pooling.
  - ReLU (p. 3): "In terms of training time with gradient descent, these saturating nonlinearities are much slower than the non-saturating nonlinearity f(x) = max(0, x). Following Nair and Hinton [20], we refer to neurons with this nonlinearity as Rectified Linear Units (ReLUs). Deep convolutional neural networks with ReLUs train several times faster than their equivalents with tanh units." Figure 1 caption: "A four-layer convolutional neural network with ReLUs (solid line) reaches a 25% training error rate on CIFAR-10 six times faster than an equivalent network with tanh neurons (dashed line)." And: "This plot shows that we would not have been able to experiment with such large neural networks for this work if we had used traditional saturating neuron models."
  - Two GPUs (p. 3): "Therefore we spread the net across two GPUs." The scheme "reduces our top-1 and top-5 error rates by 1.7% and 1.2%, respectively, as compared with a net with half as many kernels in each convolutional layer trained on one GPU."
  - Overfitting (p. 2): "The size of our network made overfitting a significant problem, even with 1.2 million labeled training examples". p. 5: "Although the 1000 classes of ILSVRC make each training example impose 10 bits of constraint on the mapping from image to label, this turns out to be insufficient to learn so many parameters without considerable overfitting."

  - Dropout (p. 6): "The recently-introduced technique, called "dropout" [10], consists of setting to zero the output of each hidden neuron with probability 0.5." Dropout roughly doubles the number of iterations required to converge."

  - No unsupervised pretraining (p. 8): "Our results show that a large, deep convolutional neural network is capable of achieving record-breaking results on a highly challenging dataset using purely supervised learning." and "To simplify our experiments, we did not use any unsupervised pre-training even though we expect that it will help".

### T18. ReLU: Nair and Hinton (2010), Glorot, Bordes, Bengio (2011)
- Sources: `nair2010rectified`, `glorot2011deep`, `lecun2015deep`, `goodfellow2016deep`.
- Nair and Hinton, abstract (p. 1, PDF): "Restricted Boltzmann machines were developed using binary stochastic hidden units. These can be generalized by replacing each binary unit by an infinite number of copies that all have the same weights but have progressively more negative biases. ... They can be approximated efficiently by noisy, rectified linear units. Compared with binary units, these units learn features that are better for object recognition on the NORB dataset and face verification on the Labeled Faces in the Wild dataset. Unlike binary units, rectified linear units preserve information about relative intensities as information travels through multiple layers of feature detectors." p. 3 (PDF): the noisy unit is "max(0, x + N(0, sigma(x)))" (symbols simplified), called "NReLU". Table 1 (p. 5, PDF), NORB test error with 4000 hidden units: NReLU 17.8% (no pretraining), 16.5% (pretrained); binary units 23.0% and 18.7%.
- Glorot, Bordes, Bengio, abstract (p. 315): "This paper shows that rectifying neurons are an even better model of biological neurons and yield equal or better performance than hyperbolic tangent networks in spite of the hard non-linearity and non-differentiability at zero, creating sparse representations with true zeros". And: "deep rectifier networks can reach their best performance without requiring any unsupervised pre-training on purely supervised tasks with large labeled datasets." p. 315: the activation "max(0, x), called the rectifier (or hinge) activation function". p. 318: "Because of this linearity, gradients flow well on the active paths of neurons (there is no gradient vanishing effect due to activation non-linearities of sigmoid or tanh units), and mathematical investigation is easier. Computations are also cheaper: there is no need for computing the exponential function in activations, and sparsity can be exploited." p. 318: "after uniform initialization of the weights, around 50% of hidden units continuous output values are real zeros" (sic). p. 318, "Potential Problems": "One may hypothesize that the hard saturation at 0 may hurt optimization by blocking gradient back-propagation." p. 321: their rectifier network without pretraining on NORB reached 16.4%, against "the 17.6% error of the nonpretrained model from Nair and Hinton (2010)".
- LeCun et al., p. 438: "At present, the most popular non-linear function is the rectified linear unit (ReLU), which is simply the half-wave rectifier f(z) = max(z, 0). In past decades, neural nets used smoother non-linearities, such as tanh(z) or 1/(1 + exp(-z)), but the ReLU typically learns much faster in networks with many layers, allowing training of a deep supervised network without unsupervised pre-training." (source prints a minus sign). Ref. 28 annotation (p. 443): Glorot et al. "showed that supervised training of very deep neural networks is much faster if the hidden layers are composed of ReLU."
- Goodfellow et al., p. 171: "In modern neural networks, the default recommendation is to use the rectified linear unit, or ReLU (Jarrett et al., 2009; Nair and Hinton, 2010; Glorot et al., 2011a), defined by the activation function g(z) = max{0, z}". p. 222 (history): see D4.

### D4. Where ReLU came from
- `goodfellow2016deep` p. 222: "Rectification using the max{0, z} function was introduced in early neural network models and dates back at least as far as the cognitron and neocognitron (Fukushima, 1975, 1980). These early models did not use rectified linear units but instead applied rectification to nonlinear functions. Despite the early popularity of rectification, it was largely replaced by sigmoids in the 1980s, perhaps because sigmoids perform better when neural networks are very small. As of the early 2000s, rectified linear units were avoided because of a somewhat superstitious belief that activation functions with nondifferentiable points must be avoided. This began to change in about 2009. Jarrett et al. (2009) observed that "using a rectifying nonlinearity is the single most important factor in improving the performance of a recognition system,"". Goodfellow p. 171 credits Jarrett 2009, Nair and Hinton 2010, Glorot et al. 2011 together.
- `krizhevsky2012imagenet` p. 3 takes the name from Nair and Hinton ("Following Nair and Hinton [20], we refer to neurons with this nonlinearity as Rectified Linear Units (ReLUs)") and mentions Jarrett et al.'s |tanh(x)|. `glorot2011deep` p. 316 credits Nair and Hinton with "promising results" in RBMs and extends the idea to deep supervised nets.
- Suggested wording: "Rectification is old (Fukushima used it); its revival as the default unit came between 2009 and 2011 (Jarrett and colleagues; Nair and Hinton, who named it; Glorot, Bordes, and Bengio, who showed it trained deep networks without pretraining)." The outline cites Nair and Hinton (2010); keep that, add the others.

## Mechanism claims to check numerically at drafting [D-009]

Suggested script: `code/checks/deep-turn.py` (standard library only), imported by `figures/deep-turn.py` [D-014]. Items 3, 5, 6, 7, and 8 were run once in this session with `python3` and agree with the sources except where D7 says otherwise.

1. **Why GPUs help: counting multiply-adds.** A layer with n inputs and m outputs applied to a batch of B examples is a matrix product needing B x n x m multiply-adds, and each of the B x m output numbers is an independent sum, so all of them can be computed at once. Tiny example: a 2 x 3 weight matrix times a 3-number input is 6 multiplications and 2 independent sums; show the 6 products laid out in a grid. Scale up: AlexNet's 4096 x 4096 fully connected layer is 16,777,216 multiply-adds per image, 2,147,483,648 per batch of 128 (its batch size, T16), all independent across the 4096 x 128 outputs. Contrast: one core doing them one after another vs hundreds of cores (Raina's GTX 280 had 240, T8). Do not attach a speed in FLOPS to any card (none sourced). Raina's measured "bigger matrices, bigger speedup" (12.9x to 72.6x, Table 2) can be printed alongside.
2. **ReLU vs sigmoid slopes.** Sigmoid slope: 0.25 at z = 0, 0.105 at z = 2, 0.0066 at z = 5; tanh slope 1 at 0, 0.0099 at z = 3. ReLU slope: 1 for z > 0, 0 for z < 0. Through 10 layers on an active path: sigmoid at best 0.25^10 = 9.5 x 10^-7; ReLU 1^10 = 1. Ties to `structure` S11 (0.25 bound). Also show the cost: an input of -2 gives output 0 and slope 0 (Glorot's "potential problem", T18).
3. **AlexNet parameter arithmetic (weights + biases), from the kernel sizes on pp. 4-5.** conv1 96 x (11 x 11 x 3) + 96 = 34,944; conv2 256 x (5 x 5 x 48) + 256 = 307,456; conv3 384 x (3 x 3 x 256) + 384 = 885,120; conv4 384 x (3 x 3 x 192) + 384 = 663,936; conv5 256 x (3 x 3 x 192) + 256 = 442,624; fc6 (6 x 6 x 256) x 4096 + 4096 = 37,752,832; fc7 4096 x 4096 + 4096 = 16,781,312; fc8 4096 x 1000 + 1000 = 4,097,000. Total 60,965,224 ("60 million", p. 5). Convolutional layers: 2,334,080 (3.8%); fc6 alone 61.9%. Assumption to state: fc6's input of 6 x 6 x 256 is not printed in the paper; it follows from 3 x 3 pooling with stride 2 (p. 4) on 13 x 13 maps (43,264 = 13 x 13 x 256, Figure 2). Checks against the caption: 186,624 = 27 x 27 x 256, 64,896 = 13 x 13 x 384, 150,528 = 224 x 224 x 3. Lesson for the reader: the convolutional layers do most of the computing with few parameters (weight sharing, `structure`), the fully connected layers hold most of the parameters. See D7(a), (d).
4. **Top-5 error, by hand.** Five images, each with one true label and a model's ranked list of five guesses; count an error only if the true label is absent from the list. Example: true labels [leopard, cherry, mite, grille, dog]; one miss gives 20% top-5 error even if the top-1 guess is wrong for three of them (top-1 error 60%).

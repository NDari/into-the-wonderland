### Base model and instruction-tuned model

### IN1. A base model is not trying to follow instructions
- Sources: `ouyang2022training`; `grattafiori2024llama`; `openai2022aligning`.
- Location: `ouyang2022training` pp. 1-2; `grattafiori2024llama` p. 3; blog, "GPT-3 models aren't trained to follow user instructions".
- Quotes: `ouyang2022training` p. 1: "these models often express unintended behaviors such as making up facts, generating biased or toxic text, or simply not following user instructions". pp. 1-2: "This is because the language modeling objective used for many recent large LMs - predicting the next token on a webpage from the internet - is different from the objective "follow the user's instructions helpfully and safely" ... Thus, we say that the language modeling objective is misaligned." `grattafiori2024llama` p. 3: "The pre-trained language model has a rich understanding of language but it does not yet follow instructions or behave in the way we would expect an assistant to." `openai2022aligning`: "This is in part because GPT-3 is trained to predict the next word on a large dataset of Internet text, rather than to safely perform the language task that the user wants. In other words, these models aren't aligned with their users."
- Note: `destination` already quotes the Llama 3 sentence (C7); do not repeat it at length. The InstructGPT p. 1-2 sentence is the cleanest definition of "misaligned" for this chapter.

### Instruction tuning before InstructGPT (2021)

### IN4. FLAN: fine-tune on many tasks written as instructions
- Source: `wei2022finetuned`
- Location: pp. 1-3, 7.
- Quotes: abstract (p. 1): "We show that instruction tuning - finetuning language models on a collection of datasets described via instructions - substantially improves zeroshot performance on unseen tasks. We take a 137B parameter pretrained language model and instruction tune it on over 60 NLP datasets verbalized via natural language instruction templates. ... FLAN substantially improves the performance of its unmodified counterpart and surpasses zero-shot 175B GPT-3 on 20 of 25 datasets that we evaluate." p. 2: "We refer to this resulting model as FLAN, for Finetuned Language Net." p. 2: "We leverage the intuition that NLP tasks can be described via natural language instructions, such as "Is the sentiment of this movie review positive or negative?" or "Translate 'how are you' into Chinese."" p. 3: "We aggregate 62 text datasets"; "each dataset is categorized into one of twelve task clusters"; "For each dataset, we manually compose ten unique templates that use natural language instructions to describe the task". Fig. 1 example (p. 1): "Here is a goal: Get a cool sleep on summer days. How would you accomplish this goal? OPTIONS: -Keep stack of pillow cases in fridge. -Keep stack of pillow cases in oven." Target: "keep stack of pillow cases in fridge". p. 7: "for small models it actually hurts generalization to unseen tasks"; "8B and smaller models, however, is thoughtprovoking - instruction tuning actually hurts performance on held-out tasks."
- Note: FLAN's base model was Google's own 137B model, not GPT-3; the comparison with GPT-3 is across models. "Zero-shot" here means "on a task type held out from instruction tuning". Bridge: this is ordinary supervised learning with the target text as the label (`pretraining`'s T5 text-to-text framing).

### IN8. Llama 2: fewer, better demonstrations; loss only on the answer
- Source: `touvron2023llama2`
- Location: p. 9.
- Quotes: "To bootstrap, we started the SFT stage with publicly available instruction tuning data (Chung et al., 2022)". "Quality Is All You Need. ### IN11. Llama 3's released code: the exact layout
- Source: `meta2024llama3code`
- Location: `llama/tokenizer.py`, class `ChatFormat` and `Tokenizer.__init__`.
- Content (code, paraphrased exactly): `encode_dialog_prompt` starts with "<|begin_of_text|>"; each message is "<|start_header_id|>" + the role name as ordinary text + "<|end_header_id|>" + "\n\n" + the message text + "<|eot_id|>"; after the last message it appends the header for an empty "assistant" message, with the comment "Add the start of an assistant message for the model to complete." The tokenizer's `stop_tokens` are "<|end_of_text|>" and "<|eot_id|>" (commented "end of turn").
- Note: so a three-message chat (system, user, then the model's turn) is one token sequence ending in an open assistant header, and generation stops at "<|eot_id|>": the hand-off from `generation` ("end-of-turn marker") and `tokens` (special tokens). The role names "system", "user", "assistant" are ordinary text between special tokens. Book 1 cannot print code [D-003]: show the layout as a figure of a text sequence (Figures planned, F2), not as code.

### IN12. Llama 2's released code: the markers were plain text
- Source: `meta2023llama2code`
- Location: `llama/generation.py`, lines 44-48 and `chat_completion`.
- Content: `B_INST, E_INST = "[INST]", "[/INST]"`; `B_SYS, E_SYS = "<<SYS>>\n", "\n<</SYS>>\n\n"`. If the first message has role "system", its text is wrapped in the <<SYS>> markers and prepended to the first user message. Each user/assistant pair is encoded as "[INST] {user} [/INST] {answer} " with beginning- and end-of-sequence tokens. An assertion message: "model only supports 'system', 'user' and 'assistant' roles, starting with 'system', then 'user' and alternating (u/a/u/a/u...)". `UNSAFE_ERROR = "Error: special tags are not allowed as part of the prompt."` is returned if any message contains one of the tags.
- Note: contrast with IN11: in Llama 2 the "special tags" are ordinary text tokenized like any other, so the code must refuse user text that contains them; Llama 3 moved the markers into dedicated special tokens. "Plain tokens" in the outline is literally true for Llama 2 and true in a stronger sense for Llama 3 (reserved IDs). Both read as "as of 2023" and "as of 2024".

### IN13. OpenAI's ChatML (2023): roles, and the injection problem
- Source: `openai2023chatml`
- Location: `chatml.md` (both versions read).
- Quotes: "Traditionally, GPT models consumed unstructured text. ChatGPT models instead expect a structured format, called Chat Markup Language (ChatML for short)." "ChatML documents consist of a sequence of messages. Each message contains a header (which today consists of who said it, but in the future will contain other metadata) and contents". The raw form: "<|im_start|>system / You are ChatGPT, a large language model trained by OpenAI. Answer as concisely as possible. / Knowledge cutoff: 2021-09-01 / Current date: 2023-03-01<|im_end|> / <|im_start|>user / How are you<|im_end|> / <|im_start|>assistant / I am doing well!<|im_end|>". "You could also represent it in the classic "unsafe raw string" format. However, this format inherently allows injections from user input containing special-token syntax, similar to SQL injections". "Note that ChatML makes explicit to the model the source of each piece of text, and particularly shows the boundary between human and AI text. This gives an opportunity to mitigate and eventually solve injections, as the model can tell which instructions come from the developer, the user, or its own input." - Source: `christiano2017deep`

### IN23. The reward model is a classifier trained on comparisons
- Source: `ouyang2022training`
- Location: pp. 8-9, 41.
- Quotes: p. 8: "Starting from the SFT model with the final unembedding layer removed, we trained a model to take in a prompt and response, and output a scalar reward. ### IN24. The RL step: maximize reward, stay near the SFT model
- Source: `ouyang2022training`
- Location: pp. 9, 42.
- Quotes: p. 9: "we fine-tuned the SFT model on our environment using PPO (Schulman et al., 2017). ### Preference optimization without RL (2023 onward)

### IN39. DPO: the same objective, trained like a classifier on the model itself
- Source: `rafailov2023direct`
- Location: pp. 1-5, 7-10.
- Quotes: abstract (p. 1): "RLHF is a complex and often unstable procedure, first fitting a reward model that reflects the human preferences, and then fine-tuning the large unsupervised LM using reinforcement learning to maximize this estimated reward without drifting too far from the original model. The resulting algorithm, which we call Direct Preference Optimization (DPO), is stable, performant, and computationally lightweight, eliminating the need for sampling from the LM during fine-tuning or performing significant hyperparameter tuning. ... fine-tuning with DPO exceeds PPO-based RLHF in ability to control sentiment of generations, and matches or improves response quality in summarization and single-turn dialogue while being substantially simpler to implement and train." p. 2: "using language models with up to 6B parameters." p. 3: "the Bradley-Terry (BT) model being a popular choice". Eq. (7), p. 4: "LDPO(πθ; πref) = -E[log σ(β log πθ(yw|x)/πref(yw|x) - β log πθ(yl|x)/πref(yl|x))]"; p. 4: "This way, we fit an implicit reward using an alternative parameterization, whose optimal policy is simply πθ." p. 5: "r̂θ(x, y) = β log πθ(y|x)/πref(y|x) is the reward implicitly defined by the language model". p. 9: "DPO has a win rate of approximately 61% at a temperature of 0.0, exceeding the performance of PPO at 57% at its optimal sampling temperature of 0.0." p. 8: win rates judged by GPT-4; "We find GPT-4 judgments correlate strongly with humans". p. 10: "How does the DPO policy generalize out of distribution, compared with learning from an explicit reward function? ... more comprehensive study is needed."

The title's "secretly a reward model" means the log-ratio is the reward. Numbers by example: Mechanism item 5. ## Disputed or inconsistent points

### IND1. Does post-training teach new abilities, or only expose old ones?
- One side: OpenAI's blog says RLHF "unlocks" capabilities GPT-3 already had, because it uses "less than 2% of the compute and data" of pretraining (`openai2022aligning`); GPT-4's exam ability "appear[s] to stem primarily from the pre-training process" (`openai2023gpt4` p. 6); LIMA proposes the "Superficial Alignment Hypothesis" (`zhou2023lima` p. 2).

- Present both; do not pick. All are 2022-2023 statements.

### IND2. Does instruction tuning help small models?

## Mechanism claims to check numerically at drafting [D-009]

Suggested script: `code/checks/instructions.py` (standard library only), imported by `figures/instructions.py` [D-014]. Items 1-4, 6 and 7 were run once in this session with `python3` and agree with the values below; item 5 uses constructed numbers and was also run.

1. **The reward model is logistic regression on a difference (Bradley-Terry).** P(A preferred over B) = σ(r_A - r_B), σ(z) = 1 / (1 + e^(-z)); loss = -log σ(r_A - r_B) when A was preferred. Checked: Δ = 0 gives 0.500 (loss 0.693); 0.5 gives 0.622 (0.474); 1 gives 0.731 (0.313); 2 gives 0.881 (0.127); 3 gives 0.953 (0.049); -1 gives 0.269 (1.313). Adding the same constant to both rewards changes nothing (σ((2+5)-(1+5)) = σ(2-1) = 0.731): the reason InstructGPT can shift rewards so demonstrations average 0 (`ouyang2022training` p. 9). The bridge sentence: "logistic regression whose single feature is the difference of two scores, and whose scores are produced by a network" (InstructGPT p. 8's "log odds" sentence supports it).
2. **Elo and reward units.** 400 / ln 10 = 173.7, matching Anthropic's "Δ(Elo Score) ≈ 174 * Δ(PM Score)" (`bai2022training` p. 12). A 174-point Elo gap gives a win probability of 0.731, the same as a reward gap of 1 (checked). Use the conventional sign (IND7).
3. **InstructGPT data arithmetic (Table 6, p. 33).** SFT train 11,295 + 1,430 = 12,725 ("about 13k"), of which customers 11.2%; RM train 6,623 + 26,584 = 33,207 ("33k"), customers 80.1%; PPO 31,144 ("31k"). Rankings of K = 4..9 give 6, 10, 15, 21, 28, 36 pairs per prompt; 33,207 prompts therefore give between 199,242 and 1,195,452 pairs, "an order of magnitude larger than the number of prompts" (p. 33). Compute (p. 17): 4.9 / 3,640 = 0.13%; 60 / 3,640 = 1.65%; together 1.78% ("less than 2%", blog). Parameters: 175 / 1.3 = 134.6 ("100x fewer"). Llama 2: 1,418,091 / 2,919,326 = 48.6% of comparisons were Meta's own.
4. **The KL penalty, by numbers (constructed).** Reward seen by the RL step = rθ(x, y) - β log(π_RL(y|x) / π_SFT(y|x)) with β = 0.02 (InstructGPT p. 42). Example: a response whose log-probability rose by 50 nats over the SFT model (summed over its tokens) pays 0.02 x 50 = 1.0 reward units, which is the whole difference between 50% and 73% preference in item 1. Label the 50 as constructed. Optional: show three candidate responses with rewards and log-ratios, and which one the penalized objective prefers.
5. **DPO's implicit reward (constructed).** r = β log(π_θ(y|x) / π_ref(y|x)), β = 0.1. Preferred answer: log-probability -40.0 under the reference model, -38.0 under the trained model: r = 0.1 x 2.0 = 0.20. Rejected answer: -35.0 to -36.0: r = -0.10. Difference 0.30; σ(0.30) = 0.574; loss 0.554 (checked). The same logistic loss as item 1, with the model's own log-probabilities as the scores. Say the log-probabilities are invented for illustration; real ones are sums over many tokens (link to `prediction`).
6. **Best-of-n and how far it moves the model (Gao et al. p. 4).** KL_bon = ln n - (n - 1)/n: n = 1: 0; 2: 0.193; 4: 0.636; 16: 1.835; 64: 3.175; 1,000: 5.909 nats (checked). Use only if the chapter shows that choosing the best of more samples is itself a stronger optimization. Llama 3 used K of 10 to 30 (`grattafiori2024llama` p. 18).
7. **Refusal counts.** XSTest Llama2.0: 38% of 250 = 95 safe prompts fully refused, 21.6% = 54 partially; any refusal 59.6% vs 29.6% without the system prompt; GPT-4 8.4% (checked). Llama 2's helpfulness-set false refusals: 1 occurrence = 0.006% and 8 = 0.05% (p. 67) imply a set of roughly 16,000 prompts; this is an inference, so do not print it as the paper's figure.
8. **Calibration repaired by temperature (constructed).** Two-option question, post-trained model gives 0.99 to one answer: logit gap ln 99 = 4.595; divided by T = 2.5 gives 1.838, probability 0.863 (checked). Shows how Kadavath et al.'s single temperature pulls an overconfident answer back; link to `generation`'s temperature. Label constructed.

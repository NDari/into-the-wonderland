## Sourced claims

### AD1. Full fine-tuning: what it is and why it became a problem
- Sources: `hu2021lora`, `houlsby2019parameter`, `li2021prefix`, `lester2021power`
- Location: Hu pp. 1, 3, 9; Houlsby pp. 2790-2791; Li and Liang p. 4582; Lester p. 3045.
- Quotes: Hu (p. 1): "Such adaptation is usually done via fine-tuning, which updates all the parameters of the pre-trained model. The major downside of fine-tuning is that the new model contains as many parameters as in the original model." Abstract (p. 1): "As we pre-train larger models, full fine-tuning, which retrains all model parameters, becomes less feasible. Using GPT-3 175B as an example - deploying independent instances of fine-tuned models, each with 175B parameters, is prohibitively expensive." p. 3: "One of the main drawbacks for full fine-tuning is that for each downstream task, we learn a different set of parameters ∆Φ whose dimension |∆Φ| equals |Φ0|." p. 9: fine-tuning GPT-3 175B "in the usual way" is hard "due to the large checkpoint it produces and the high hardware barrier to entry since it has the same memory footprint as pre-training." Houlsby (abstract, p. 2790): "in the presence of many downstream tasks, fine-tuning is parameter inefficient: an entire new model is required for every task." p. 2793: "For N tasks, full fine-tuning requires N × the number of parameters of the pre-trained model." Li and Liang (p. 4582): fine-tuning "requires updating and storing all the parameters of the LM"; "GPT-2 has 774M parameters (Radford et al., 2019) and GPT-3 has 175B parameters". Lester (p. 3045) names it "model tuning (or "fine-tuning"), where all model parameters are tuned during adaptation, as proposed by Howard and Ruder (2018)."
- Note: two costs, to keep apart in the text: storage and serving (one full copy per task) and training memory (gradients and optimizer state for every parameter, AD2). Hu p. 1 footnote 1 says that for GPT-3 "fine-tuning boosts its performance significantly" over few-shot (Appendix A, not read): a pointer to `prompting`.

### AD2. The memory bill of full fine-tuning, as stated in the sources
- Sources: `rajbhandari2020zero`, `dettmers2023qlora`, `hu2021lora`
- Location: ZeRO p. 8; QLoRA p. 1 (NeurIPS); Hu p. 5.
- Quotes: ZeRO (p. 8): mixed-precision Adam keeps "an fp32 copy of the parameters, momentum and variance, with memory requirements of 4Ψ, 4Ψ, and 4Ψ bytes, respectively"; "Mixed-precision Adam has K = 12. In total, this results in 2Ψ + 2Ψ + KΨ = 16Ψ bytes of memory requirement. For a model such as GPT-2 with 1.5 Billion parameters, this leads to a memory requirement of at least 24 GB, which is significantly higher than the meager 3 GB of memory required to hold the fp16 parameters alone." QLoRA (p. 1): "regular 16-bit finetuning of a LLaMA 65B parameter model [58] requires more than 780 GB of GPU memory." Hu (p. 5): "For a large Transformer trained with Adam, we reduce that VRAM usage by up to 2/3 if r ≪ dmodel as we do not need to store the optimizer states for the frozen parameters. On GPT-3 175B, we reduce the VRAM consumption during training from 1.2TB to 350GB."
- Note: `training` already teaches the 16 bytes per parameter (from ZeRO); reuse it, do not re-derive. The three sources imply different bytes per parameter (16; 780/65 = 12.0; 1,200/175 = 6.9): see ADD1. All exclude or do not state activation memory.

### AD3. T5 (2019): updating all parameters beat the cheaper methods tried then
- Source: `raffel2020exploring`
- Location: pp. 29-30, 42, 57.
- Quotes: p. 29: "we focus on two alternative fine-tuning approaches that update only a subset of the parameters of our encoder-decoder model. The first, "adapter layers" (Houlsby et al., 2019; Bapna et al., 2019), is motivated by the goal of keeping most of the original model fixed while fine-tuning. Adapter layers are additional dense-ReLU-dense blocks that are added after each of the preexisting feed-forward networks in each block of the Transformer." "When finetuning, only the adapter layer and layer normalization parameters are updated." "The second alternative fine-tuning method we consider is "gradual unfreezing" (Howard and Ruder, 2018)." p. 30: "lower-resource tasks like SQuAD work well with a small value of d whereas higher resource tasks require a large dimensionality to achieve reasonable performance. This suggests that adapter layers could be a promising technique for fine-tuning on fewer parameters as long as the dimensionality is scaled appropriately to the task size." "We found that gradual unfreezing caused a minor degradation in performance across all tasks, though it did provide some speedup during fine-tuning." Table 10 (p. 30): All parameters GLUE 83.28, CNNDM 19.24, SQuAD 80.88, SGLUE 71.36, EnDe 26.98, EnFr 39.82, EnRo 27.65; adapters d = 32: 80.52, 15.08, 79.32, 60.40, 13.84, 17.88, 15.54; d = 512: 81.54, 17.78, 79.18, 64.30, 23.45, 33.98, 25.81; gradual unfreezing: 82.50, 18.95, 79.17, 70.79, 26.71, 39.02, 26.93. p. 42: "We found that the basic approach of updating all of a pre-trained model's parameters during fine-tuning outperformed methods that are designed to update fewer parameters, although updating all parameters is most expensive."

### AD4. Catastrophic forgetting: the 1989 discovery, as reviewed by French (1999)
- Source: `french1999catastrophic` (for McCloskey and Cohen 1989 and Ratcliff 1990, not fetched)
- Location: pp. 128-129.
- Quotes: abstract (p. 128): "Only rarely does new learning in natural cognitive systems completely disrupt or erase previously learned information; that is, natural cognitive systems do not, in general, forget 'catastrophically'. Unfortunately, though, catastrophic forgetting does occur under certain circumstances in distributed connectionist networks. The very features that give these networks their remarkable abilities to generalize, to function in the presence of degraded input, and so on, are found to be the root cause of catastrophic forgetting." p. 128: "another was discovered by McCloskey and Cohen1 and Ratcliff 2. ... They observed that under certain conditions, the process of learning a new set of patterns suddenly and completely erased a network's knowledge of what it had already learned. They referred to this phenomenon as catastrophic interference (or catastrophic forgetting) and suggested that the underlying reason for this difficulty was the very thing - a single set of shared weights - that gave the networks their remarkable abilities to generalize and degrade gracefully." "Catastrophic interference is a radical manifestation of a more general problem for connectionist models of memory - in fact, for any model of memory - the so-called 'stability-plasticity' problem". The experiment (pp. 128-129): "a standard backpropagation network9 thoroughly learned a set of 'one's addition facts' (i.e. the 17 sums 1+1 through 9+1 and 1+2 through 1+9). Then the network learned the 17 'two's addition facts' ... Within 1-5 learning trials of the two's addition facts, the number of correct responses on the one's addition facts had dropped from 100% to 20%. By five more learning trials, this percentage had dropped to 1%, and by 15 trials, no correct answers from the previous one's addition problems could be produced by the network." (The extraction drops the plus signs, "111 through 911"; restored here from context: 17 sums.) Human contrast (p. 128): Barnes and Underwood's forgetting curve "was relatively gradual". p. 129: "These two papers are generally given credit for bringing the problem of catastrophic interference to the attention of the connectionist community." Reference 1 (p. 134): McCloskey, M. and Cohen, N. (1989), in The Psychology of Learning and Motivation (Vol. 24) (Bower, G.H., ed.), pp. 109-164, Academic Press.
- Note: the reader may know backpropagation as a "1990s technique": this is a problem found in exactly that era, with the network the reader knows. Keep the term history straight: the 1989 title says "interference"; French gives both names. `pretraining` says ULMFiT's authors "called" it catastrophic forgetting, which is accurate as a quotation; this chapter should give the 1989 origin so that no reader concludes ULMFiT coined it (ADD3).

### AD5. The classic remedy: rehearse the old while learning the new
- Sources: `french1999catastrophic`, `kirkpatrick2017overcoming`
- Location: French p. 133 (Box); Kirkpatrick p. 1.
- Quotes: French (p. 133, box): the Original patterns "are no longer available, and therefore cannot be interleaved with the New patterns to be learned"; Robins' pseudopatterns "approximate the originally learned function, f, and can be interleaved with the new patterns to be learned to prevent catastrophic forgetting of the original patterns. So, just as rehearsing on previously learned patterns prevents a network from forgetting those patterns, rehearsing on pseudopatterns that approximate the function defined by the originally learned patterns ..." Kirkpatrick (p. 1): "By interleaving data from multiple tasks during learning, forgetting does not occur because the weights of the network can be jointly optimized for performance on all tasks." Replaying stored data "is impractical for learning large numbers of tasks, as in our setting it would require the amount of memories being stored and replayed to be proportional to the number of tasks."
- Note: the reader's bridge: mixing old data into training is like refitting on the union of two training sets. Do not claim that LLM fine-tuning recipes all mix in pretraining data: no source here says so.

### AD6. Elastic weight consolidation (2017): a spring on the important weights
- Source: `kirkpatrick2017overcoming`
- Location: pp. 1-4 (arXiv PDF).
- Quotes: abstract (p. 1): "Neural networks are not, in general, capable of this and it has been widely thought that catastrophic forgetting is an inevitable feature of connectionist models. ... Our approach remembers old tasks by selectively slowing down learning on the weights important for those tasks." p. 1: the phenomenon "occurs specifically when the network is trained sequentially on multiple tasks because the weights in the network that are important for task A are changed to meet the objectives of task B." p. 2: "This constraint is implemented as a quadratic penalty, and can therefore be imagined as a spring anchoring the parameters to the previous solution, hence the name elastic. Importantly, the stiffness of this spring should not be the same for all parameters; rather, it should be greater for those parameters that matter most to the performance during task A." p. 3: the posterior is approximated as a Gaussian with "a diagonal precision given by the diagonal of the Fisher information matrix F"; the loss is "L(θ) = LB(θ) + Σi (λ/2) Fi (θi - θ*A,i)^2, where LB(θ) is the loss for task B only, λ sets how important the old task is compared to the new one and i labels each parameter." p. 4 (Fig. 2 and text): with a fixed quadratic constraint per weight ("L2 regularization") "the performance in task A degrades much less severely, but task B cannot be learned properly".
- Note: the bridge is the reader's ridge regression, with the penalty centred on the old weights instead of zero and a different strength per weight. One paragraph at most; EWC was shown on MNIST variants and Atari, not on LLMs. Venue: PNAS 2017 (metadata only).

### AD7. Forgetting in LLM fine-tuning: one empirical study (preprint)
- Source: `luo2023empirical`
- Location: PDF pp. 1-2, 6-7.
- Quotes: abstract (p. 1): "This study empirically evaluates the forgetting phenomenon in LLMs' knowledge during continual instruction tuning from the perspectives of domain knowledge, reasoning, and reading comprehension. The experiments reveal that catastrophic forgetting is generally observed in LLMs ranging from 1b to 7b parameters. Surprisingly, as the model scale increases, the severity of forgetting intensifies in such a model sale range which may result from the much significant initial performance in the larger LLM." "our findings indicate that general instruction tuning can help alleviate the forgetting phenomenon in LLMs during subsequent fine-tuning." p. 6: models trained with Adam, learning rate 2e-5, 3 epochs per task (all parameters; no LoRA mentioned). p. 7: "the performance of BLOOMZ-7.1b on MMLU-SocialScience in Figure 3 drops from 36.18% to 26.06% after continual training."
- Note: date it ("a 2023 study of models of 1 to 7 billion parameters"); it is a preprint ("Under review", v5 of January 2025). Its scale finding is a single study's result, not a law (ADD4). Five instruction tasks in sequence, then general benchmarks re-measured: the 1989 design, at LLM scale.

### AD8. LoRA forgets less, and learns less (2024)
- Source: `biderman2024lora`
- Location: PDF pp. 1-2.
- Quotes: abstract (p. 1): "we compare the performance of LoRA and full finetuning on two target domains, programming and mathematics. We consider both the instruction finetuning (≈100K prompt-response pairs) and continued pretraining (≈20B unstructured tokens) data regimes. Our results show that, in the standard low-rank settings, LoRA substantially underperforms full finetuning. Nevertheless, LoRA better maintains the base model's performance on tasks outside the target domain. We show that LoRA mitigates forgetting more than common regularization techniques such as weight decay and dropout; it also helps maintain more diverse generations. Finally, we show that full finetuning learns perturbations with a rank that is 10-100× greater than typical LoRA configurations". p. 1: "the jury is still out on whether it compromises performance compared to full finetuning". p. 2: "In continued pretraining, the performance gap between full finetuning and LoRA is not closed even with high ranks. In instruction finetuning, on the other hand, high ranks can match full finetuning performance." "we perform a singular value decomposition to show that full finetuning barely changes the spectrum of the base model's weight matrices, and yet the difference between the two (i.e. the perturbation) is high rank." "We find that LoRA is very sensitive to hyperparameters". Models: Llama-2-7B (p. 2).
- Note: the counterweight to LoRA's own claims (ADD5), and a good ending for the forgetting thread: a small update changes less, for better and worse. The phrase "a form of continual learning" (p. 1) links fine-tuning to AD4.

### AD9. Adapters (2019): small bottleneck layers inserted into a frozen network
- Source: `houlsby2019parameter`
- Location: pp. 2790-2794.
- Quotes: abstract (p. 2790): "As an alternative, we propose transfer with adapter modules. Adapter modules yield a compact and extensible model; they add only a few trainable parameters per task, and new tasks can be added without revisiting previous ones. The parameters of the original network remain fixed, yielding a high degree of parameter sharing. ... On GLUE, we attain within 0.4% of the performance of full fine-tuning, adding only 3.6% parameters per task. By contrast, fine-tuning trains 100% of the parameters per task." p. 2791: "networks forget previous tasks after re-training (McCloskey & Cohen, 1989; French, 1999). Adapters differ in that the tasks do not interact and the shared parameters are frozen. This means that the model has perfect memory of previous tasks using a small number of task-specific parameters." p. 2791: "Adapter modules have two main features: a small number of parameters, and a near-identity initialization." "By initializing the adapters to a near-identity function, original network is unaffected when training starts." p. 2792: "The adapters first project the original d-dimensional features into a smaller dimension, m, apply a nonlinearity, then project back to d dimensions. The total number of parameters added per layer, including biases, is 2md + d + m. By setting m ≪ d, we limit the number of parameters added per task; in practice, we use around 0.5 - 8% of the parameters of the original model." Figure 2 caption (p. 2792): "We add the adapter module twice to each Transformer layer"; "The adapter also contains a skip-connection." p. 2793: BERT-LARGE "contains 24 layers, and a total of 330M parameters"; "Adapters achieve a mean GLUE score of 80.0, compared to 80.4 achieved by full fine-tuning." Adapter sizes tried {8, 64, 256}; "To solve all of the datasets in Table 1, fine-tuning requires 9× the total number of BERT parameters. In contrast, adapters require only 1.3× parameters." Table 1 (p. 2794): BERT-LARGE 9.0×, 100%, 80.4; Adapters (8-256) 1.3×, 3.6%, 80.0; Adapters (64) 1.2×, 2.1%, 79.6. On 17 further tasks with BERT-BASE (p. 2793, Table 2 p. 2794): adapters 0.4% behind, "1.14% new parameters per task, resulting in 1.19× parameters for all 17 tasks". p. 2794: tuning the layer normalization parameters alone ("40k for BERTBASE") "performs poorly". p. 2794: fine-tuning only the top layer of BERT-BASE gives "approximately 9M trainable parameters and 77.8%" on MNLIm, while an adapter of size 64 gives "approximately 2M trainable parameters and 83.7%" (full fine-tuning 84.4%).
- Note: "within 0.4%" is 0.4 points of GLUE score (80.4 vs 80.0), about 0.5% relative (ADD6). The paper says "3%" in its introduction and section 3 and "3.6%" in the abstract and Table 1: use 3.6% (the table). Their setting was a cloud service where tasks "arrive in a stream" (p. 2790): one frozen model, many small add-ons. Bridge: the bottleneck is an autoencoder-like squeeze (d to m to d) inside the network. The near-identity start is the same idea as LoRA's zero start (AD13).

### AD10. Prefix tuning (2021): learned "virtual tokens" in front of every layer
- Source: `li2021prefix`

### AD13. LoRA (2021): the mechanism
- Source: `hu2021lora`
- Location: pp. 1-5.
- Quotes: abstract (p. 1): "We propose Low-Rank Adaptation, or LoRA, which freezes the pretrained model weights and injects trainable rank decomposition matrices into each layer of the Transformer architecture, greatly reducing the number of trainable parameters for downstream tasks." p. 2: "We take inspiration from Li et al. (2018a); Aghajanyan et al. (2020) which show that the learned over-parametrized models in fact reside on a low intrinsic dimension. We hypothesize that the change in weights during model adaptation also has a low "intrinsic rank"". p. 4: "For a pre-trained weight matrix W0 ∈ R^(d×k), we constrain its update by representing the latter with a low-rank decomposition W0 + ∆W = W0 + BA, where B ∈ R^(d×r), A ∈ R^(r×k), and the rank r ≪ min(d, k). During training, W0 is frozen and does not receive gradient updates, while A and B contain trainable parameters." "h = W0x + ∆Wx = W0x + BAx (3)". "We use a random Gaussian initialization for A and zero for B, so ∆W = BA is zero at the beginning of training. We then scale ∆Wx by α/r, where α is a constant in r." p. 4: "When deployed in production, we can explicitly compute and store W = W0 + BA and perform inference as usual. ... When we need to switch to another downstream task, we can recover W0 by subtracting BA and then adding a different B'A', a quick operation with very little memory overhead." p. 5: "this guarantees that we do not introduce any additional latency during inference compared to a fine-tuned model by construction." p. 4: "as we increase the number of trainable parameters, training LoRA roughly converges to training the original model". p. 5: "We limit our study to only adapting the attention weights for downstream tasks and freeze the MLP modules". p. 6: "|Θ| = 2 × L̂LoRA × dmodel × r, where L̂LoRA is the number of weight matrices we apply LoRA to." Limitation (p. 5): "it is not straightforward to batch inputs to different tasks with different A and B in a single forward pass, if one chooses to absorb A and B into W". p. 9: "Our method uses a similar bottleneck structure to impose a low-rank constraint on the weight updates. The key functional difference is that our learned weights can be merged with the main weights during inference".
- Note: this is the key figure's content. Formula allowed [D-002]: W = W0 + BA, with W0 (frozen, d x k), B (d x r), A (r x k), r the rank; optionally the α/r scale in one sentence. The B = 0 start mirrors Houlsby's near-identity start (AD9): training begins exactly at the pretrained model. LoRA does not reduce the cost of inference; it reduces training memory and per-task storage.

### AD15. QLoRA (2023): LoRA on top of a 4-bit frozen model
- Source: `dettmers2023qlora`
- Location: pp. 1-6, 9, 18-19, 26 (NeurIPS pagination).
- Quotes: abstract (p. 1): "We present QLoRA, an efficient finetuning approach that reduces memory usage enough to finetune a 65B parameter model on a single 48GB GPU while preserving full 16-bit finetuning task performance. QLoRA backpropagates gradients through a frozen, 4-bit quantized pretrained language model into Low Rank Adapters (LoRA). Our best model family, which we name Guanaco, outperforms all previous openly released models on the Vicuna benchmark, reaching 99.3% of the performance level of ChatGPT while only requiring 24 hours of finetuning on a single GPU. QLoRA introduces a number of innovations to save memory without sacrificing performance: (a) 4-bit NormalFloat (NF4), a new data type that is information theoretically optimal for normally distributed weights (b) Double Quantization to reduce the average memory footprint by quantizing the quantization constants, and (c) Paged Optimizers to manage memory spikes." p. 2: "QLoRA reduces the average memory requirements of finetuning a 65B parameter model from >780GB of GPU memory to <48GB without degrading the runtime or predictive performance compared to a 16-bit fully finetuned baseline." p. 3: block-wise quantization: "chunk the input tensor into blocks that are independently quantized, each with their own quantization constant c." p. 4: "QLoRA has one low-precision storage data type, in our case usually 4-bit, and one computation data type that is usually BFloat16. NF4 rationale (p. 4): "pretrained neural network weights usually have a zero-centered normal distribution"; quantile quantization "ensures each quantization bin has an equal number of values assigned from the input tensor." p. 5: "using 32-bit constants and a blocksize of 64 for W, quantization constants add 32/64 = 0.5 bits per parameter on average"; double quantization reduces this "to 8/64 + 32/(64 · 256) = 0.127 bits, a reduction of 0.373 bits per parameter." p. 2: double quantization saves "an average of about 0.37 bits per parameter (approximately 3 GB for a 65B model)". p. 5: paged optimizers use "NVIDIA unified memory" so optimizer states are "automatically evicted to CPU RAM when the GPU runs out-of-memory"; p. 5: "we only compute weight gradients for the LoRA parameters which use 16-bit BrainFloat." p. 2 (Table 1, column "Size"): Guanaco 65B "41 GB", 33B "21 GB", 13B "10 GB", 7B "6 GB"; the text on the same page says the 7B model "requires just 5 GB of memory" when deployed (minor inconsistency; avoid or give the table's number). p. 2: "a 9k sample dataset (OASST1) outperformed a 450k sample dataset (FLAN v2, subsampled) on chatbot performance".
- Note: "99.3% of ChatGPT" is a score on the Vicuna benchmark ("a set of 80 prompts", p. 21) as judged by GPT-4, and the same abstract says "current chatbot benchmarks are not trustworthy to accurately evaluate the performance levels of chatbots" (p. 1). Do not repeat 99.3% without both qualifiers, or leave it out (ADD7). `local` will own quantization in depth; this chapter needs only "store weights in 4 bits, compute in 16".

That last clause is an inference from two vendors, not a sourced survey: phrase it as such or drop it. Google and other vendors were not checked.

### AD25. The low-rank theorem (1936): keep the largest singular values
- Source: `eckart1936approximation`
- Location: pp. 211, 216 (p. 216 read on the page image).
- Quotes: abstract (p. 211): "The mathematical problem of approximating one matrix by another of lower rank is closely related to the fundamental postulate of factor-theory. When formulated as a least-squares problem, the normal equations cannot be immediately written down, since the elements of the approximate matrix are not independent of one another. The solution of the problem is simplified by first expressing the matrices in a canonic form. It is found that the problem always has a solution which is usually unique." p. 211: "If N individuals are each subjected to n tests, it is a fundamental postulate of factor theory that the resulting n × N score matrix a can be adequately approximated by another matrix β whose rank r is less than the smaller of n or N." p. 216: "The procedure of finding β may be summarized: (1.) express a in the canonic form of Eq. (12.1); (2.) replace all but r of the diagonal elements of λ by zeros, beginning with the smallest and continuing in order of increasing magnitude. (3.) The resulting matrix is μ, and β is given by Eq. (12). The solution is unique unless λr = λr+1." "The minimum value of x² is x² = Σ (i = r+1 to R) λi² (R being the rank of a and the multipliers being numbered as before)."
- Note: the canonic form is what is now called the singular value decomposition; the λi are the singular values (Eckart and Young do not use the word "singular value"; say "what we now call"). The error formula is the check for mechanism item 3. The setting, test scores of individuals in psychometrics, is itself a bridge to the reader's factor analysis and PCA.

### AD26. PCA as the best low-rank approximation (textbook statement)
- Source: `hastie2009elements`
- Location: section 14.5.1, pp. 534-535.
- Quotes: p. 534: "The principal components of a set of data in IR^p provide a sequence of best linear approximations to that data, of all ranks q ≤ p." p. 535: minimizing the reconstruction error Σ ||xi - μ - Vq λi||² over rank-q models; "construct the singular value decomposition of X: X = UDV^T"; "D is a p × p diagonal matrix, with diagonal elements d1 ≥ d2 ≥ ... ≥ dp ≥ 0 known as the singular values. For each rank q, the solution Vq to (14.53) consists of the first q columns of V. The columns of UD are called the principal components of X".
- Note: the reader's own textbook statement. `embeddings` already uses SVD for LSA (its ledger E6 and mechanism item 3): this chapter can say "the same tool as LSA and PCA" and point back. The difference to state plainly: PCA and truncated SVD find a low-rank approximation of a known matrix; LoRA learns a low-rank update by gradient descent and never computes an SVD (ADD11).

## Disputed or inconsistent points

### ADD1. How many bytes per parameter does full fine-tuning need?
- ZeRO (p. 8): 16 bytes per parameter for mixed-precision Adam (2 weights + 2 gradients + 12 optimizer state), activations extra. QLoRA (p. 1): ">780 GB" for 16-bit fine-tuning of 65B, which is 12.0 bytes per parameter (780/65). LoRA (p. 5): 1.2 TB for GPT-3 175B, which is 6.9 bytes per parameter, and 350 GB with LoRA, which is the 16-bit weights alone (175B x 2 bytes). Neither QLoRA nor LoRA gives its breakdown.
- Suggested handling: use ZeRO's itemized 16 bytes per parameter (already in `training`) for the chapter's own 8B arithmetic, and quote the papers' totals as their reported figures with "as reported", noting that accountings differ (precision of optimizer states, sharding, what is counted). Do not derive one from another.

### ADD2. T5 Table 10 prints the adapter d = 2048 row twice
- `raffel2020exploring` Table 10 (p. 30): the d = 2048 row (81.51, 16.62, 79.47, 63.03, 19.83, 27.50, 22.63) is identical to the d = 128 row. The full results table (Table 16, p. 57) gives d = 2048 as GLUE 82.62, CNNDM 18.30, SQuAD 79.40, SGLUE 68.61, EnDe 25.64, EnFr 36.92, EnRo 26.93. Same in arXiv v4. If the chapter shows T5's comparison, use Table 16 for d = 2048 and say so in the ledger at drafting; the conclusion (all parameters best) is unchanged either way.

### ADD3. Who named catastrophic forgetting
- French (p. 128): McCloskey and Cohen (1989) and Ratcliff (1990) "referred to this phenomenon as catastrophic interference (or catastrophic forgetting)". The 1989 title uses "interference" (French's reference 1). The 1989 text was not read, so whether it also says "forgetting" is unverified. Kirkpatrick et al. (p. 1) cite French, McCloskey and Cohen, McClelland et al. 1995, and Ratcliff for the term "catastrophic forgetting". `pretraining` quotes ULMFiT using the term (accurately).
- Suggested wording: "first described in 1989 by Michael McCloskey and Neal Cohen, who called it catastrophic interference; 'catastrophic forgetting' is the name that stuck." Do not credit ULMFiT or Kirkpatrick et al. with the term.

### ADD4. Does forgetting get worse or better with model size?
- `luo2023empirical` (preprint): within 1B to 7B, larger models forgot more, possibly because they started higher. No counter-source was fetched. Present as one study's finding with its range and status ("a 2023 preprint found ... between 1 and 7 billion parameters"), not as a general law.

### ADD5. Does LoRA match full fine-tuning?
- For: `hu2021lora` (pp. 1, 8): "on-par or better" on RoBERTa, DeBERTa, GPT-2, GPT-3 (GLUE, E2E, WikiSQL, MNLI, SAMSum); `dettmers2023qlora` (p. 6): QLoRA with NF4 "replicates both 16-bit full finetuning and 16-bit LoRA finetuning performance" on GLUE, Super-NaturalInstructions, and (versus 16-bit LoRA) MMLU, but full fine-tuning was not compared at 33B and 65B (p. 9), and only with LoRA on all linear layers (p. 18).
- Against: `biderman2024lora` (pp. 1-2): on code and math with Llama-2-7B, LoRA "substantially underperforms" full fine-tuning in standard low-rank settings; the gap is not closed in continued pretraining even at high rank; high ranks can match in instruction fine-tuning. Full fine-tuning's weight change is high rank (10-100 times typical LoRA ranks). Hu et al. themselves (p. 10, footnote 6) expected a small rank to fail on, for example, a new language.
- Suggested handling: both, dated. LoRA matches full fine-tuning on tasks close to what the model already does (2021-2023 benchmarks); it falls short when the new domain is far or the data large (2024), and in exchange forgets less. This is a fair summary of the fetched sources, not a settled consensus.

### ADD6. "Within 0.4%" (Houlsby et al.)
- Table 1 (p. 2794): 80.0 vs 80.4 GLUE score: 0.4 points, 0.5% relative. The paper's "0.4%" is points. Say "0.4 points" or give both numbers.

### ADD7. Guanaco's "99.3% of ChatGPT"
- `dettmers2023qlora` abstract: 99.3% on the Vicuna benchmark (GPT-4 as judge); the same abstract says current chatbot benchmarks "are not trustworthy"; p. 21 reports "moderate agreement among human annotators (Fleiss κ = 0.42)" and p. 22 a weaker sample-level agreement between GPT-4 and humans (κ = 0.25). A headline number that the paper itself qualifies. If used, give the benchmark, the judge, and the caveat; better, use the memory claim (65B on one 48 GB GPU) as the paper's lasting contribution.

### ADD8. Was Hinton et al.'s distilled model smaller?
- In the MNIST experiment, yes (two layers of 1200 units to 800). In the speech experiment, no: the aim was to beat "a model of the same size" (p. 4), and the "cumbersome model" is an ensemble of ten baseline-architecture models (p. 5). The distilled model's size is not stated beyond that; "same size as the baseline" is the reading of p. 4. Do not write that the 2015 speech result compressed a large model into a smaller one; it compressed ten into one.

### ADD9. "60% faster" (DistilBERT)
- Table 3: 668 s vs 410 s. 410/668 = 0.61 (39% less time); 668/410 = 1.63 (63% more throughput). The paper's "60% faster" matches the throughput reading, rounded down. Also, p. 4 reports SQuAD "79.8 F1 and 70.4 EM" for the two-step distillation while Table 2 prints 79.1/86.9 (EM/F1) for DistilBERT (D): an internal inconsistency; avoid SQuAD numbers. Table 3's caption calls STS-B "sentiment analysis"; it is a sentence-similarity task (paper's error; irrelevant if not quoted).

### ADD10. "Distillation" means two things in LLM writing
- Hinton's sense (match the teacher's soft distribution; Gemma 2, p. 1, p. 3) versus supervised fine-tuning on teacher-generated text (DeepSeek-R1, p. 11, which calls it "this straightforward distillation method"). Both are in use as of 2025. Define the first; name the second as a looser use; do not pick one as "correct".

### ADD11. LoRA is not an SVD
- The bridge (outline: "low-rank approximation is the same idea as truncated SVD or PCA") is right about the shape of the object: a rank-r matrix written as a product of a tall and a wide matrix, with r(d + k) numbers instead of dk. It is wrong if read as "LoRA computes an SVD": LoRA learns B and A by gradient descent from a zero start (AD13), and no matrix is decomposed. Hu et al. use SVD only to analyse learned updates (pp. 11-12). Eckart and Young say which rank-r matrix is closest to a given matrix; LoRA bets that the needed change is close to some rank-r matrix and searches for it. Biderman et al. found that full fine-tuning's actual change is high rank for hard domains (ADD5): the bet can lose.

## Mechanism claims to check numerically at drafting [D-009]

Suggested script: `code/checks/adapting.py` (numpy for item 3; standard library otherwise), imported by `figures/adapting.py` [D-014]. All arithmetic below was run once in this session (scratch script, not in the repository) and agrees with the statements.

1. **The key figure's counts.** A 4,096 x 4,096 projection (Llama 3 8B's query and output matrices, AD27; GPT-3 6.7B has the same width per `book1/sources/anatomy.md`, not re-checked here): 16,777,216 weights. LoRA at rank r adds r x (4,096 + 4,096) = 8,192 r: r = 1: 8,192 (0.049%); r = 4: 32,768 (0.195%); r = 8: 65,536 (0.391%, 1/256 of the matrix); r = 16: 131,072 (0.781%); r = 64: 524,288 (3.125%). General rule for a d x k matrix: r(d + k) vs dk; a saving only while r < dk/(d + k) (2,048 for a square 4,096 matrix).
2. **LoRA on a whole model.** (a) GPT-3 175B (96 layers, d = 12,288), Wq and Wv only: 96 x 2 x (12,288 + 12,288) = 4,718,592 per unit of rank; r = 1: 4.7M, r = 4: 18.9M, r = 8: 37.7M, matching Hu et al. Tables 4-5. 175,255.8M / 18.87M = 9,285; 350 GB / 35 MB = 10,000; 18.87M x 2 bytes = 37.7 MB ("roughly 35MB"). (b) Llama 3 8B (AD27): per layer, per unit of rank: q (4,096 x 4,096) 8,192; k and v (4,096 x 1,024) 5,120 each; o 8,192; gate and up (4,096 x 14,336) 18,432 each; down 18,432; total 81,920; times 32 layers: 2,621,440 per unit of rank. All linear layers at r = 8: 20,971,520 (0.261% of 8,028,164,096); r = 16: 41,943,040 (0.522%); r = 64 (QLoRA's setting): 167,772,160 (2.090%). Wq and Wv only: (8,192 + 5,120) x 32 = 425,984 per unit of rank.
3. **Truncated SVD on a small matrix (the bridge).** Build a small matrix with known, quickly falling singular values (for example 8 x 8 or 10 x 6, so that low rank actually saves numbers; a 6 x 6 matrix at rank 3 needs 3 x 12 = 36 numbers, no saving). Show: the rank-k truncation's error (Frobenius) equals the square root of the sum of the discarded squared singular values (Eckart and Young p. 216); a rank-k projection onto a random subspace is much worse; the share of the squared norm kept. Checked here on a 6 x 6 example with singular values 10, 5, 1, 0.5, 0.2, 0.1: rank 1 keeps 79.18%, error 5.1284 = sqrt(25 + 1 + 0.25 + 0.04 + 0.01); rank 2 keeps 98.97%, error 1.1402; random rank-2 subspace error 9.57. Use integer-friendly or seeded values, printed to the chapter's precision. Also show B x A reproducing the rank-k matrix with B = U_k S_k (d x k) and A = V_k^T (k x n): the LoRA shape.
4. **A tiny LoRA training run is not needed** (Book 1 has no code and the outline does not ask for one); if a numeric illustration of "B = 0 at the start" is wanted, one line suffices: W0 + B A with B = 0 equals W0 exactly.
5. **Memory for adapting an 8B model (8,028,164,096 parameters), weights and optimizer only, no activations; label as such.** Full fine-tuning at 16 bytes per parameter (ZeRO, AD2): 128.5 GB. LoRA r = 16, all linear layers: frozen 16-bit weights 2 bytes x N = 16.06 GB, plus 41.9M trainable at 16 bytes = 0.67 GB: 16.73 GB. QLoRA: NF4 4 bits + 0.127 bits of constants with double quantization = 0.516 bytes per parameter: 4.14 GB, plus the same adapters 0.67 GB: 4.81 GB. Caveat to state: this assumes every weight is quantized; if the 1,048,576,000 embedding and output parameters stay in 16 bits (a common implementation choice, not verified in a source here) the QLoRA total is 6.37 GB. Treating LoRA parameters at 16 bytes each (16-bit weight and gradient plus 32-bit Adam state) is this ledger's assumption; QLoRA (p. 5) says LoRA parameters "use 16-bit BrainFloat" and its p. 26 measures 26 MB for 0.2% of a 7B model (14M parameters x 2 bytes = 28 MB, consistent with 16-bit storage). Print beside it QLoRA's measured 7B breakdown (AD16): base 5,048 MB, adapters 26 MB, input gradients 567 MB (18 MB per sequence with checkpointing).
6. **QLoRA's own arithmetic.** 32/64 = 0.5 bits; 8/64 + 32/(64 x 256) = 0.1270; saving 0.3730 bits per parameter; for 65B: 65e9 x 0.373 / 8 = 3.03 GB ("approximately 3 GB"). 65B at 4.127 bits = 33.5 GB, under 48 GB. 780 GB / 65B = 12.0 bytes per parameter (ADD1); 16 bytes x 65B = 1,040 GB.
7. **Adapters.** Houlsby's 2md + d + m with d = 1,024 (BERT-LARGE), m = 64: 132,160 per adapter; two per layer, 24 layers: 6,343,680, about 1.9% of 330M (Table 1 prints 2.1% for size 64, which also counts layer norms and the classifier, so print the paper's number and the computation separately). Nine GLUE tasks at 3.6% each: 1 + 9 x 0.036 = 1.32 ("1.3x"). 80.4 - 80.0 = 0.4 points = 0.50% relative.
8. **Prompt tuning and intrinsic dimension.** 5 tokens x 4,096 = 20,480; 11e9 / 20,480 = 537,109 ("over five orders of magnitude"). Li et al.: 750 / 199,210 = 0.38% (printed "0.4%"); 199,210 - 750 = 198,460.
9. **Distillation numbers.** Hinton speech: (60.8 - 58.9) / (61.1 - 58.9) = 86.4% ("more than 80%"). DistilBERT: 66/110 = 0.600; 77.0/79.5 = 0.969; 668/410 = 1.63; 410/668 = 0.61 (ADD9). Optional: a soft-target example reusing `generation`'s temperature script: one teacher distribution at T = 1 and T = 4 showing the "BMW / garbage truck / carrot" ratios surviving at higher T (constructed numbers; say so).
